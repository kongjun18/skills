# HTML Format

Read before writing. The template, [tutorial-template.html](../assets/tutorial-template.html), already contains the styles and scripts; write content with the components below and do not add styles unless a component is missing.

## File

- Path: `<project-root>/tutorials/<slug>.html`, slug in kebab case (`raft-log-replication.html`). One file per tutorial; images, if any, in `tutorials/<slug>-assets/`, linked relatively.
- `<html data-kind>`: `repo`, `concept`, or `research`.
- Meta: `tutorial-subject`, `tutorial-generated` (YYYY-MM-DD), and for repo tutorials `source-commit` (full hash). Delete `source-commit` for other kinds.
- The page is self-contained: inline CSS and JS. Mermaid, KaTeX, and highlight.js load from a CDN only when the page uses them, so diagrams, math, and highlighting need internet; everything else works offline.

## Structure

Section ids the check script requires: `objectives`, `prerequisites`, `big-picture`, `summary`, `glossary`, `further-reading`, and `walkthrough` for repo tutorials. Each lesson is `<section class="lesson" id="<slug>">` with one `<h2>`; use `<h3>` inside a lesson for sub-steps. The table of contents and reading time are generated by the script; do not write them.

## Components

| Need | Markup |
| --- | --- |
| Key idea of a lesson | `<div class="callout key"><p>...</p></div>` |
| Misconception | `<div class="callout pitfall"><p>...</p></div>` |
| Optional depth | `<details class="aside"><summary>Going deeper: ...</summary>...</details>` |
| Check-yourself | `<details class="check"><summary>question</summary><div class="answer"><p>...</p></div></details>` |
| Term, first use | `<dfn id="d-<term>">term</dfn>` plus a glossary entry `<dt id="g-<term>">` |
| Term, later use | `<a class="term" href="#g-<term>">term</a>` (link the first few uses in later lessons, not every one) |
| Walkthrough steps | `<ol class="steps"><li>...</li></ol>` |
| Comparison | a plain `<table>` with a header row |

## Code

Generate each citation and excerpt with the bundled script, then paste its output and trim:

```bash
python3 <skill>/scripts/excerpt.py --repo <repo-root> --commit <source-commit> \
  --tutorial tutorials/<slug>.html --lang c src/sched.c:120-148
```

- Output: `<a class="src" data-loc="src/sched.c:120-148" href="...">src/sched.c:120–148</a>` then `<pre><code class="language-c">` with the escaped lines. Put the citation at the end of the sentence that introduces the excerpt, so it sits just above the code. A citation without an excerpt goes at the end of the sentence it supports.
- `data-loc` is `path:LINE` or `path:START-END`, relative to the repository root; the check script verifies it at the pinned commit with `--repo`.
- `href`: a GitHub permalink at the pinned commit when that commit is on a remote branch; otherwise a relative path from the tutorial to the file in the working tree. The script warns when the working-tree file differs from the commit; then tell the reader in the header that links show the current files.
- Trim long excerpts by replacing lines with a comment marker (`// ...`); keep the `data-loc` range of the full span.

## Diagrams

- Default: Mermaid inside a figure — `<figure><pre class="mermaid">flowchart TD ...</pre><figcaption>...</figcaption></figure>`. Use `flowchart` for structure and data flow, `sequenceDiagram` for interactions over time, `stateDiagram-v2` for state machines. Quote labels containing punctuation: `A["put(k, v)"]`.
- The column is narrow (46rem). Keep at most about four nodes per row: use `TD`, or split a long chain with `subgraph`s. Render and check that labels are readable.
- Avoid `<`, `>`, and `&` in Mermaid labels (the HTML parser reads them before Mermaid does); paraphrase (`name/SKILL.md`, "a to b").
- Inline `<svg>` when Mermaid cannot express the picture (memory layouts, timelines, geometric ideas). Use `currentColor` for strokes and text so it works in dark mode, and set a `viewBox`.
- Every figure has a caption saying what to notice.

## Math

Inline `\( ... \)`, display `\[ ... \]`; KaTeX renders them. Math inside `<pre>` or `<code>` is left alone. Use math only when the learner's background includes it; otherwise say it in words.

## Further reading

An ordered `<ol class="reading">`: each item is a link to a source you opened (a web page, or a file in the studied repository), its title, and one line on what it adds and when to read it. `check_tutorial.py --check-urls` verifies the web links.
